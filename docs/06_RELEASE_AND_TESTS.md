# 06 — Milestones, quality gates and acceptance

- M0: Code hygiene, CI, design tokens, docs, preview configuration and a working build.
- M1: Complete accessible responsive public site and honest signup/login placeholders.
- M2: Verified authentication, invitations, ownership checks, multi-tenant membership, row-level isolation and audit.
- M3: Distinct authorized workspaces plus real company workforce/training/evidence records.
- M4: WSP/ATR planning, review/signoff, frozen versions, configurable verified-only rule engine.
- M5: Finance states, support administration, performance/security/accessibility hardening and documented pilot.

## Per-milestone requirement
Record changed routes/components/migrations, proof of tests, preview URL only if it exists, relevant requirement IDs, open blockers and explicit signoff. Stop at review gates.

## Test criteria
Type checking, lint, build, public navigation smoke tests, responsive/keyboard testing, tenant isolation in APIs/database/downloads, import duplicate/idempotency, evidence controls, review permission and rule-engine locked-off behavior.

## Regulatory hard stop
First SETA UNKNOWN. No fabricated filing dates, codes, templates or production official outputs.
